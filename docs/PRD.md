## 1. 项目概述

为卡丁车赛道设计的便携式 GPS 圈速计时器，安装在方向盘上，实时显示与最佳圈的时间差值（Delta），帮助车手在驾驶过程中精确定位每个弯角的快慢，并记录完整轨迹数据供赛后分析。

## 2. 目标用户

- 租赁卡丁车爱好者
- 会去不同赛道
- 需要在驾驶中实时获取圈速反馈
- 需要赛后导出数据用专业软件分析

### 重量与振动注意事项

- 总重量估算：~250g（含电池）。AiM MyChron5 为 390g，Alfano 7 为 435g，本设备更轻
- 外壳建议用 PETG（比 PLA 更耐热耐冲击）
- 所有内部组件用泡棉或硅胶垫固定，防止振动松脱
- Type-C 充电口外露，供充电和固件更新

## 5. 功能需求

### 5.1 核心功能：Position-Based 实时 Delta 计时

**优先级：P0（v1.0）**

- **基于参考圈多段线进度的 Delta 计算**（Polyline Progress Delta）：
  1. 将最佳圈的 GPS 轨迹存储为有序坐标点序列（参考多段线）
  2. 每次 GPS 更新时，将当前坐标投影到参考多段线上，计算沿线进度（0.0 ~ 1.0）
  3. 查找参考圈在相同进度处的时间戳，计算差值
  4. **航向过滤**：当前航向与参考多段线该段的航向差 > 90° 时，不更新 Delta（防止平行赛道段误匹配）
  5. **最大横向距离阈值**：当前坐标到参考多段线的垂直距离 > 30m 时，Delta 显示冻结并标记"OFF TRACK"
- **PPS 校时**：BK-880 的 PPS 引脚连接 ESP32 GPIO，通过硬件中断捕获精确的 GPS 秒脉冲（精度 ±30ns），消除 UART 传输延迟不确定性（10-50ms），为每个 GPS fix 提供微秒级时间基准
- Delta 精度目标：**±50ms**（PPS 校时 + 25Hz GPS + 样条插值）
- 过线计时精度：
  - **需求（可防御）**：**±30ms**
  - **目标（最佳情况）**：±20ms（PPS + Catmull-Rom 样条插值，参考 FoxLAP 实测 12ms vs MyLaps）
  - 注：25Hz 采样间隔 40ms，样条插值可在采样点之间估算穿越时刻，但 GPS 位置噪声（CEP ~1.5m）限制了绝对下限
- Delta 屏幕显示分辨率：**0.01s**（百分之一秒，与 MyChron/Alfano 一致）
- 颜色编码：绿色 = 快于参考圈，红色 = 慢于参考圈
- **首圈无参考圈时**：Delta 显示 "--"，仅记录数据，首个有效圈完成后自动作为参考

### 5.2 过线检测（起终线和扇区线）

**优先级：P0（v1.0）**

每条检测线定义为：两点经纬度 + 合法穿越方向

检测逻辑：
1. **有符号线段交叉检测**：判断连续两个 GPS 点是否穿过检测线
2. **航向窗口**：当前航向必须在检测线法线方向 ±60° 以内（防止反方向穿越误触发）
3. **单次触发（Arming）**：每条检测线穿越一次后进入"已触发"状态，必须远离检测线一定距离（>50m）后重新激活
4. **最小时间间隔**：
   - 最小圈时间：15 秒（防止 GPS 抖动在终点线附近连续触发）
   - 最小扇区时间：5 秒
5. **PPS 校时 + 样条插值**：利用 PPS 精确时间基准，在两个 GPS 采样点之间用 Catmull-Rom 样条插值精确计算穿越时间点
6. **去抖（与精确计时解耦）**：
   - **精确时间戳路径**：检测到线段交叉后，立即用样条插值回溯计算精确穿越时刻（不等待确认）
   - **去抖验证路径**：连续 2 个 GPS 采样确认穿越方向一致后，才正式确认该穿越事件有效
   - 如果去抖验证失败（GPS 抖动导致的假穿越），丢弃已计算的时间戳
   - 两条路径独立运行：去抖不增加计时延迟，仅决定穿越事件是否被采纳

### 5.3 扇区计时

**优先级：P0（v1.0）**

- 每条赛道最多 **4 个扇区**（即最多 3 条扇区分割线 + 1 条起终线）
- 扇区分割线与起终线使用相同的检测逻辑
- 实时显示已完成扇区的 Delta
- GPS 抖动在短扇区上影响大，故限制最少 2 个扇区

### 5.4 最佳圈定义

**优先级：P0（v1.0 仅支持 Session Best，v1.1 扩展）**

- **v1.0**：本次 Session 最佳圈（每次开机重新计算）
- **v1.1**：增加历史最佳圈（跨 Session 保留，存储在 SD 卡），可通过 Web 界面切换
- 参考圈需存储完整 GPS 轨迹数据（约 50-100KB/圈，25Hz 下 40 秒一圈约 1000 个坐标点）

### 5.5 无效圈自动过滤

**优先级：P0（v1.0）**

圈状态定义：

| 状态 | 说明 | 计入统计？ |
|------|------|-----------|
| `timed` | 正常计时圈 | ✅ |
| `out` | 出发圈（首次穿越起终线之前） | ❌ |
| `slow` | 圈速 > 当前最佳圈 × 150% | ❌ |
| `short` | 圈时间 < 最小圈时间（15秒） | ❌ |
| `no_ref` | 无参考圈的首圈 | ✅（作为首个参考） |

失效规则：
- 首次穿越起终线前的所有数据为 `out` 状态
- 没有最佳圈时，第一个完整圈自动成为参考，状态为 `no_ref`
- `slow` 和 `short` 圈不更新最佳圈，不影响 Delta 参考基准
- v1.1 增加：Web 界面手动标记/取消

### 5.6 赛道管理

**优先级：P0（v1.0）**

- 预存赛道库，保存在 SD 卡中
- 每条赛道包含：
  - 赛道名称（ASCII only，v1.0 不支持中文文件名）
  - 赛道 ID
  - 起终线坐标（两点经纬度 + 合法穿越方向向量）
  - 扇区分割线坐标（每条也是两点经纬度 + 方向向量，最多 3 条）
  - 赛道中心坐标（用于自动识别）
  - 赛道近似长度（用于辅助识别）

### 5.7 赛道自动识别

**优先级：P0（核心自动识别为 v1.0，多候选交互选择延期到 v1.1）**

识别逻辑：
1. GPS 定位成功后，搜索赛道库中中心坐标距当前位置 < 5km 的赛道
2. 如果匹配到 1 条，直接使用，屏幕显示"已识别：XX"
3. 如果匹配到 0 条，屏幕提示"未知赛道，请用手机配置"
4. 识别结果可通过 Web 界面修改

**v1.0 当前范围：**

- 若 5km 内存在多条候选赛道，设备自动选择最近的一条
- 用户仍可通过手机 Web 界面手动切换赛道

**延期到 v1.1：**

- 如果匹配到多条（同一场馆多个布局），在 Web 界面上手动选择

### 5.8 赛道创建

**优先级：P0（v1.0 仅手动输入，v2.0 扩展）**

**v1.0**：在手机 Web 界面中手动输入起终线和扇区的经纬度坐标

**v1.1**：赛后从已保存的 GPS 轨迹中标记起终线和扇区（在 Web 界面上拖拽轨迹上的点）

**v2.0**：在手机 Web 界面的卫星地图上点选（需解决 ESP32 热点下无互联网的问题，可能需要 Station 模式或预缓存地图瓦片）

### 5.9 数据记录

**优先级：P0（v1.0）**

- GPS 锁定 25Hz 刷新率（v1.0 不提供可选，确保 Delta 精度）
- 自动保存到 SD 卡，无需手动操作
- 文件格式：VBO（Racelogic VBOX 格式）
- 文件命名：`YYYYMMDD_TrackName_HHMMSS_NNN.vbo`（ASCII only）
  - 示例：`20260402_ShanghaiKartCenter_143022_001.vbo`
- 兼容 Circuit Tools、VBOX Tools 等分析软件

### 5.10 断电保护

**优先级：P0（v1.0）**

卡丁车振动大，Type-C 接触不良可能导致瞬断。必须防止数据丢失：

1. **写入策略**：VBO 数据写入临时文件 `_recording.vbo.tmp`，每 30 秒执行一次 `fsync` 刷盘
2. **Session 完成时**：关闭文件，原子重命名为最终文件名
3. **开机恢复**：启动时扫描 SD 卡根目录是否存在 `.tmp` 文件，如果有则：
   - 视为上次异常断电的未完成 Session
   - 重命名为 `YYYYMMDD_UNKNOWN_HHMMSS_recovered.vbo`（从文件内容提取时间戳）
   - 屏幕提示"已恢复上次未完成的 Session"
4. **Session 元数据 JSON**：仅在 Session 正常结束时写入，断电丢失 JSON 可接受（VBO 数据不丢）

### 5.11 VBO 文件格式

**文件编码**：ASCII only
**行结尾**：Windows CR+LF（`\r\n`），包括最后一行
**时间**：UTC

GPS 坐标格式：**角分制**
- 纬度：`十进制度 × 60`，`+` = 北纬，`-` = 南纬
- 经度：`十进制度 × -60`，`+` = 西经，`-` = 东经（注意：东经为负）
- 格式字符串：`%+012.5f`

文件结构：

```
File created on DD/MM/YYYY at HH:MM:SS\r\n
\r\n
[header]\r\n
satellites\r\n
time\r\n
latitude\r\n
longitude\r\n
velocity kmh\r\n
heading\r\n
height\r\n
\r\n
[comments]\r\n
Generated by KartGPS v1.0\r\n
Log Rate (Hz) : 25.00\r\n
\r\n
[session data]\r\n
name TrackName\r\n
\r\n
[laptiming]\r\n
Start  +MMMMM.MMMMM +MMMMM.MMMMM +MMMMM.MMMMM +MMMMM.MMMMM Start / Finish\r\n
Split  +MMMMM.MMMMM +MMMMM.MMMMM +MMMMM.MMMMM +MMMMM.MMMMM Split 1\r\n
\r\n
[column names]\r\n
sats time lat long velocity heading height\r\n
\r\n
[data]\r\n
008 143000.000 +01874.12345 -07258.67890 045.200 128.50 +00032.10\r\n
...
```

数据列格式：

| 列 | 格式 | 示例 | 说明 |
|----|------|------|------|
| sats | `%03d` | `008` | 3 位零填充 |
| time | `HHMMSS.SSS` | `143000.000` | UTC，无冒号，毫秒分辨率 |
| lat | `%+012.5f` | `+01874.12345` | 角分，+ 北 |
| long | `%+012.5f` | `-07258.67890` | 角分，- 东 |
| velocity | `%07.3f` | `045.200` | km/h |
| heading | `%06.2f` | `128.50` | 度 |
| height | `%+09.2f` | `+00032.10` | 米，WGS84 |

**验收标准**：生成的 VBO 文件必须能在 Circuit Tools 中正确导入并显示圈速和轨迹。项目需包含黄金测试文件（golden test files）用于回归验证。

### 5.12 手机交互（WiFi + Web 界面）

**优先级：P0（v1.0 基础版）**

- ESP32 自建 WiFi 热点
- SSID：`KartGPS-XXXX`（XXXX 为设备 MAC 后四位）
- 密码：可配置，默认 `kartgps123`
- 访问地址：`http://192.168.4.1`

**重要约束**：记录模式下 WiFi 功能受限（降低优先级/限制并发请求），避免影响 GPS 数据处理和 SD 卡写入的实时性。WiFi 主要在停车/赛后使用。

## 6. 屏幕 UI 设计

### 6.1 驾驶界面（默认，唯一的赛道中屏幕）

**设计原则**：驾驶中只需余光瞥一眼。一个巨大的 Delta 数字 + 颜色 = 全部信息。

```
┌─────────────────────────────────┐
│                                 │
│                                 │
│         -0.23s                  │  ← 巨大字体，绿色背景（快）或红色背景（慢）
│                                 │
│                                 │
├─────────────────────────────────┤
│  Lap 7         Best: 42.956    │  ← 小字，弱化
└─────────────────────────────────┘
```

状态变体：
- **正常**：绿色/红色背景 + 白色大 Delta 数字
- **无参考圈（首圈）**：黑色背景 + 白色 "--"
- **OFF TRACK（偏离赛道 >30m）**：黄色背景 + "OFF TRACK"
- **GPS 信号丢失**：灰色背景 + "NO GPS"

## 7. 系统工作流程

```
[开机]
  │
  ▼
[GPS 搜星] ← 屏幕显示卫星数量，等待 3D Fix
  │
  ▼ (3D Fix, 卫星 ≥ 6)
  │
[自动匹配赛道]
  │
  ├── 匹配 1 条 → 屏幕显示"已识别：XX"
  ├── 匹配多条 → 进入 Web 界面手动切换
  └── 匹配 0 条 → 屏幕提示"用手机配置"
  │
  ▼
[Ready - 等待起跑]
  │
  ▼ (首次穿越起终线 → 开始计时)
  │   (同时 SD 卡开始写入 VBO 临时文件)
  │
[计时中]
  │
  ├── 每 40ms (25Hz) → GPS 更新 → 写入 VBO → 计算 Delta
  ├── 穿越扇区线 → 记录扇区时间
  ├── 穿越起终线 → 完成一圈
  │   ├── 判断圈状态 (timed / slow / short)
  │   └── 如果是新最佳 → 更新参考圈
  ├── 每 30 秒 → fsync 刷盘
  │
  ▼ (用户关机)
  │
[正常结束]
  ├── 关闭 VBO 文件
  ├── 原子重命名 .tmp → 最终文件名
  ├── 写入 Session 元数据 JSON
  └── 断电
```

## 8. 任务调度与资源管理

ESP32-S3 双核任务分配：

| 核心 | 任务 | 优先级 | 说明 |
|------|------|--------|------|
| Core 0 | GPS UART 接收 + NMEA 解析 + PPS 中断 | 最高 | UART 环形缓冲 ≥ 1KB，PPS 硬件中断，不允许被任何任务阻塞 |
| Core 0 | 过线检测 + Delta 计算 | 高 | 每次 GPS 更新后立即执行，必须在下一个 GPS fix 到来前完成（<40ms） |
| Core 1 | SD 卡 VBO 写入（异步队列） | 中高 | GPS 数据写入环形队列，Core 1 异步消费写入 SD 卡，每 30s fsync |
| Core 1 | TFT 屏幕渲染 | 中 | 目标 10 FPS，仅刷新变化区域（局部刷新） |
| Core 1 | WiFi Web Server | 低 | 记录模式下限制并发，仅响应基本请求 |
| Core 1 | 按键输入处理 | 低 | 去抖 50ms |

关键约束：
- **GPS 计时路径零阻塞**：Core 0 只做 GPS 接收、解析、过线检测、Delta 计算，不做任何 I/O 阻塞操作
- **SD 写入异步化**：GPS 数据先写入内存环形队列（PSRAM，容量 ≥ 5 秒数据），Core 1 的 SD 写入任务从队列消费。即使 SD 卡写入偶尔延迟（FAT32 簇分配），也不影响 Core 0 的计时精度
- **SPI 总线互斥**：SD 卡写入和 TFT 屏幕渲染共用 SPI 总线，通过 mutex 互斥，SD 写入优先级高于屏幕渲染
- WiFi 在记录模式下为尽力服务（best-effort），不保证响应速度

## 10. 技术约束

- GPS 坐标系：WGS84
- GPS 锁定 25Hz，多星座模式下若不支持则降至 10Hz
- VBO 坐标格式：角分制（十进制度 × 60），东经为负
- VBO 文件编码：ASCII only，CR+LF 行尾
- VBO 时间：UTC
- SPI 总线：屏幕和 SD 卡共用，通过互斥锁（mutex）保证不冲突
- PSRAM 8MB：用于屏幕帧缓冲和参考圈 GPS 轨迹数据
- 内部 SRAM：用于 GPS UART 缓冲、NMEA 解析、实时计算
- 参考圈存储：约 50-100KB/圈（25Hz × 40s × 每点约 20 字节）
- 电池续航：需实测，目标 ≥ 8 小时
- 工作温度：-20°C ~ 70°C

## 11. 验收测试计划

| 测试项 | 方法 | 通过标准 |
|--------|------|----------|
| VBO 导入 | 在 Circuit Tools 中导入生成的 VBO 文件 | 正确显示轨迹、圈速、扇区 |
| 过线检测精度 | 用已知赛道真实 GPS 数据回放 | 与 MyLaps 官方计时差值 < 30ms（需求），目标 < 20ms |
| Delta 稳定性 | 连续 10 圈相同走线 | Delta 在直道上不出现 >0.1s 的异常跳变 |
| GPS 计时路径延迟 | 在 25Hz 记录模式下测量 Core 0 处理时间 | GPS fix 到达 → 过线检测完成 < 10ms（不被 SD/WiFi 阻塞） |
| 断电恢复 | 记录中拔电，重启 | 恢复的 VBO 文件可正常导入 |
| 赛道识别 | 在赛道库中有 5 条赛道，到达其中一条 | 10 秒内正确识别 |
| SD 卡长时间写入 | 连续记录 2 小时 | 无数据丢失、无文件损坏 |
